# 对话分享链接的脱敏处理

记录日期：2026-10-29

> 本文只保留方法，**不记录任何真实标识**：具体用户名、账号 ID、公司域、项目代号、出口 IP 都在
> 本机私有规则文件 `tools/scrub-rules.json`（已被 `.gitignore` 排除）里，仓库只放形状示例
> `tools/scrub-rules.example.json`。

## 一、分享链接的内容来源

WorkBuddy 的对话分享页是**发布时的云端快照**，不是实时读取本地会话文件。以本次为例：

```
https://workbuddy.link/p/<pageId>?shareId=...
  └─ 页面壳（几 KB），内含 __PUBLISH_BOOTSTRAP__
       └─ 快照目录 https://<static-host>/page/<nodeId>/<hash>/
            ├── index.html            加载官方渲染器
            └── conversation-data.json 对话正文（含全部路径，体量最大的一部分）
```

渲染器地址 `<...>/page/page_comm/conversation/v1/index.js` 与 `style.css`，
运行时用 `new URL('conversation-data.json', window.location.href)` 取同目录数据。

**由此得出两条结论：**

1. 修改本地 `~/.workbuddy/projects/<slug>/<sessionId>.jsonl` **不会**改变已经发布的分享链接。
   本地会话与云端快照是两份独立的数据（体量与命中次数都不同）。
2. 想要干净的分享内容，只能**替换数据文件后重新发布**，或者另建一个页面。

## 二、处理流程

### 1. 取回快照

```bash
curl -s "https://workbuddy.link/p/<pageId>" -o page.html
# 从 page.html 里找 __PUBLISH_BOOTSTRAP__ 的 artifact.url，得到 page/<nodeId>/<hash>/
curl -s "<artifact.url>conversation-data.json" -o conversation-data.json
curl -s "<artifact.url>index.html"          -o index.html
```

### 2. 替换敏感串

```bash
# 先准备本机私有规则（不会被提交）
cp tools/scrub-rules.example.json tools/scrub-rules.json
# 再按自己的标识改一遍，然后运行
node tools/scrub-share.mjs conversation-data.json share-clean/conversation-data.json
```

脚本按顺序做纯文本替换，输出每条规则的命中数与残留检查；退出码 2 表示仍有残留。
规则文件形状：

```json
{
  "rules": [["原值", "替换值"]],
  "leftover": ["替换后仍需为 0 的残留词"]
}
```

要覆盖的典型几类：本地用户名（含 8.3 短名）、账号 UUID、公司域 / 邮箱域、项目代号、
仓库目录别名、车辆/设备等个人物件名称、出口 IP。

### 3. 组装可托管目录

```
share-clean/
├── index.html              页面壳，引用同目录资源
├── renderer.js             官方渲染器（复制自 <...>/page_comm/conversation/v1/index.js）
├── style.css               官方样式
└── conversation-data.json  已脱敏数据
```

三个资源必须同目录：渲染器按模块地址解析样式，按页面地址解析数据。

### 4. 本地预览

```bash
node tools/serve-share.mjs share-clean 7799
# 打开 http://127.0.0.1:7799/
```

## 三、注意事项

- `share-clean/` 是一次性中间产物（十几 MB），不入库；需要时按「二、处理流程」重建，用完整目录删掉。
- 渲染器是从 CDN 直接取回的第三方产物，本地托管只为让数据取同源文件；上游更新后需重新拉取。
- 官方 CDN 不返回 `Access-Control-Allow-Origin`，所以不能跨域引用，只能整包搬到同源目录。
- 本工作区**同时只能存在一个已发布应用**：发布 `share-clean` 会覆盖同名应用上的
  「Agent 任务中心」。发布前务必确认。
- 脱敏只针对快照文本，不涉及 `h5/`、`prototype/` 里的演示数据（那部分此前已单独处理）。

## 四、替换表的形状（不含真实值）

| 类别 | 替换为 | 说明 |
|---|---|---|
| 用户名 / 8.3 短名 | `dev` / `DEV` | 路径与 toast 里最常出现的标识 |
| 账号 UUID | 全零 UUID | 出现在 workspace-directories 等元数据里 |
| 公司域 / 邮箱域 | `example` / `example.com` | Java 包名与邮箱后缀两处都要换 |
| 项目代号（三种大小写） | `ORDER` / `Order` / `order` | 大小写各写一条，长串在前 |
| 仓库目录别名 | `workspace` | 只影响本地路径，不影响内容 |
| 个人物件名称 | 中性名称 | 车辆、设备、商品等 |
| 出口 IP | `203.0.113.10` | 文档保留地址段 |

脱敏后做两项确认：脚本的残留检查通过（退出码 0），页面用无头 Edge 实拍能正常渲染。
