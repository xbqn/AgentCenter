## 1. 背景与问题

当前开发者同时使用多款 AI 编程/通用 Agent 工具（CodeBuddy、WorkBuddy、Trae、OpenCode、AtomCode、DeepSeek、Claude Code、Codex、豆包、千问等）。这些工具各自为政，**没有统一视角回答三个基本问题**：

1. **这段时间 Agent 到底干了什么？**
2. **哪些干完了，哪些还欠着，哪些半途而废？**
3. **它们一共占了本地多少空间，留下了多少中间垃圾文件？**

现状痛点：

- 会话记录散落在十几个不同目录，格式各异（JSONL / SQLite / IndexedDB / 目录树），人工翻查成本极高。
- 没有跨工具的任务状态视图，**中断的会话很容易被遗忘**，几天后才发现事情没做完。
- Agent 产生的中间文件（临时脚本、缓存、调试产物、快照回滚文件）持续堆积，占用磁盘且无人回收。
- 缺少周期性回看机制，无法沉淀「一天干了哪些活」的时间账。

**AgentCenter 的定位**：一个**本地优先、只读扫描**的 Agent 任务中心。统一采集各 Agent 的会话记录，解析为统一任务模型，输出仪表盘、日报与待办清单。

### 1.1 设计原则

| 原则 | 说明 |
|---|---|
| 只读 | 只读取 Agent 数据目录，绝不修改、删除、迁移 Agent 的原始会话文件 |
| 本地优先 | 全部解析在本地完成，不上传任何对话内容到云端（可选开启 LLM 摘要时才例外，且明确提示） |
| 可插拔 | 每个 Agent 一个适配器，用户可自行新增/替换解析规则 |
| 零侵入 | 不劫持 Agent 进程，不注入 Hook，纯旁路扫描（可选提供轻量心跳写入以增强实时性） |
| 双入口 | 同一份数据，既能在 Obsidian 内看，也能被任意 Agent 通过 MCP 查询 |

## 2. 目标用户与核心场景

### 2.1 目标用户

- **多 Agent 并行使用者**：同时开 3–6 个 Agent 工具工作的开发者/团队（主要场景）。
- **技术负责人 / 团队 Owner**：需要知道团队机器上 AI 到底产出了什么、耗时几何。
- **重度知识管理者**：用 Obsidian 做第二大脑，希望把「Agent 干了什么」沉淀进笔记体系。

### 2.2 核心场景

| 编号 | 场景 | 触发方式 | 输出 |
|---|---|---|---|
| SC-1 | **今日干了什么** | 手动 / 每日 17:00 定时 | 日报 Markdown + Dashboard 当日视图 |
| SC-2 | **干活进度追踪** | 每 10 分钟定时扫描 | 进行中任务实时状态、活跃心跳 |
| SC-3 | **待办盘点** | 手动 / 每日定时 | 跨 Agent 汇总的未完成事项清单 |
| SC-4 | **中断复盘** | 手动 | 中断任务列表 + 中断原因 + 最后一条消息上下文 |
| SC-5 | **空间治理** | 手动 / 每周定时 | 各 Agent 占用排行、中间文件清单、可回收量估算 |
| SC-6 | **向 Agent 追问** | 在 WorkBuddy/Qoder/DeepSeek 等对话里自然语言提问 | MCP 工具返回结构化答案 |

### 2.3 反向场景（明确不做）

- ❌ 不做 Agent 之间的任务编排/派发，AgentCenter 只做**观测**。
- ❌ 不替代 Obsidian 的搜索，不做全文检索引擎（仅做元数据与轻量内容索引）。
- ❌ 不上传会话内容到云端做 AI 分析（本地可选的轻量规则摘要除外）。

## 3. 功能需求

编号规则：`FR-<模块>-<序号>`。优先级：P0 必须 / P1 重要 / P2 可选。

### 3.1 采集模块 FR-SC

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-SC-01 | 支持扫描 CodeBuddy、Trae、WorkBuddy、zcode、OpenCode、AtomCode、DeepSeek 桌面版、Codex、Claude Code、豆包工作、千问工作共 **11 个内置适配器** | P0 | 每个适配器在对应工具已安装的机器上能列出会话并解析出标题/时间 |
| FR-SC-02 | 每个适配器提供 **Windows / macOS / Linux 三平台默认路径**，自动探测安装状态（是否存在、有无新会话） | P0 | 安装即自动启用；未安装则置灰并提示 |
| FR-SC-03 | 用户可**自定义路径**（支持多路径、单文件直选） | P0 | 自定义路径覆盖默认值，且可一键恢复默认 |
| FR-SC-04 | 用户可**新增自定义 Agent 适配器**：指定名称、路径、文件通配符、字段映射 | P1 | 新增后无需改代码即可完成采集 |
| FR-SC-05 | 增量扫描：记录每个文件 `mtime + size` 指纹，未变更文件不重复解析 | P0 | 二次扫描耗时 < 首扫的 15% |
| FR-SC-06 | 单文件解析失败不影响整体，失败项进入错误队列并可在 UI 查看 | P0 | 一个坏文件不导致整次扫描失败 |
| FR-SC-07 | 扫描全程只读，不创建/修改/删除源目录内任何文件 | P0 | 源目录 `mtime` 与文件数在扫描前后一致 |

### 3.2 解析与建模模块 FR-NM

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-NM-01 | **统一任务模型**：把各 Agent 的会话切分为「任务(Task)」，同一会话可含多个任务 | P0 | 见 §4.2 数据模型 |
| FR-NM-02 | 提取任务元信息：标题、所属 Agent、项目/工作目录、起止时间、消息数、工具调用数 | P0 | Dashboard 与详情页字段齐全 |
| FR-NM-03 | 识别**中间文件**（工具写文件但未出现在最终交付清单中的产物） | P1 | 能区分「交付物」与「中间/临时文件」并标注 |
| FR-NM-04 | 统计**存储占用**：会话级 + Agent 级 + 可回收中间文件量 | P0 | 占用数值与磁盘实际偏差 < 5% |
| FR-NM-05 | 计算**两种耗时**：墙钟时长 / 活跃时长（剔除 >5min 空隙） | P0 | 两者同时展示，口径在 UI 中注明 |
| FR-NM-06 | 解析出**待办事项**：从助手消息中的勾选清单、"下一步/待补充"等结构抽取 | P1 | 跨 Agent 汇总后去重，可手动勾销 |
| FR-NM-07 | 标记**中断**：会话以错误/中止结束，或心跳超时 | P0 | 中断任务在 Dashboard 高亮，可查看中断点上下文 |

### 3.3 展示模块 FR-UI

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|

### 3.4 调度模块 FR-SCH

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-SCH-01 | 支持**多档定时策略**：固定间隔（如 10 分钟）、每日定点（如 17:00）、每周、手动 | P0 | 每条策略可独立启停、独立配置 |

## 4. 数据设计

### 4.1 目录结构

```
agentcenter/
├── obsidian-plugin/          # Obsidian 插件（TypeScript）
│   ├── manifest.json
│   ├── main.ts               # 插件入口：注册视图/命令/设置页
│   ├── src/
│   │   ├── views/            # Dashboard / Detail / Sidebar 视图
│   │   ├── settings.ts       # Obsidian SettingTab
│   │   ├── report.ts         # 日报 Markdown 渲染
│   │   └── scheduler.ts      # 插件内调度器
│   └── styles.css
├── core/                     # 跨 Agent 扫描内核（Node，零依赖优先）
│   ├── src/adapters/         # 11 个内置适配器 + 通用 JSONL 适配器
│   ├── src/model.ts          # 统一数据模型
│   ├── src/segment.ts        # 会话 → 任务切分
│   ├── src/analyze.ts        # 状态判定 / 耗时 / 存储统计
│   ├── src/scan.ts           # 扫描调度与增量
│   └── src/store.ts          # 索引读写
├── mcp/                      # MCP Server（stdio）
└── cli/                      # 命令行入口
```

### 4.2 统一任务模型

```ts
interface TaskRecord {
  taskId: string;              // `${agentId}:${sessionId}:${seq}`
  agentId: string;             // 'workbuddy'
  agentName: string;           // 'WorkBuddy'
  sessionId: string;
  title: string;               // 首条用户消息摘要（≤60 字）
  project: string;             // 工作目录 / 项目名
  cwd: string;
  startedAt: number;           // epoch ms
  endedAt: number | null;
  wallClockMs: number;         // 墙钟时长
  activeMs: number;            // 活跃时长（剔除 >5min 空隙）
  messageCount: number;
  userMessageCount: number;
  toolCallCount: number;
  status: 'completed' | 'running' | 'interrupted' | 'failed' | 'waiting' | 'pending';
  statusReason: string;        // 判定依据（可解释性）
  artifacts: ArtifactRef[];    // 交付物
  intermediateFiles: FileRef[];// 中间文件
  todos: TodoItem[];           // 待办抽取
  storageBytes: number;
  lastMessagePreview: string;
  sourceFile: string;          // 原始会话文件路径
}

interface ArtifactRef  { path: string; type: 'doc'|'code'|'image'|'sheet'|'unknown'; bytes: number; final: boolean }
interface FileRef      { path: string; bytes: number; reason: string }
interface TodoItem     { id: string; text: string; done: boolean; source: string }
```

### 4.3 索引存储

| 文件 | 位置 | 说明 |
|---|---|---|
| `index.json` | `.obsidian/plugins/agentcenter/` | 任务索引（主数据） |
| `fingerprints.json` | 同上 | 每个源文件的 `mtime/size/sha`，用于增量扫描 |
| `scans.json` | 同上 | 扫描历史记录 |
| `日报/YYYY-MM-DD.md` | 用户 Vault 指定目录 | 生成的日报 |

索引规模估算：单任务记录约 1.5–3 KB，1 万任务约 30 MB，JSON 全文加载在 Obsidian 中可接受；超出后按月分片（`index/2026-10.json`）。

## 5. 界面需求（原型见 `prototype/index.html` 与 `h5/index.html`）

两套原型均为单文件 HTML，浏览器直接打开即可评审，无构建、无外部依赖：

- `prototype/index.html`：**Obsidian 主区域视图**的桌面形态。左侧导航切换 9 个页面，任务行点击下钻；右下角「主视图 / 分屏 480」可切换宽度，用于检查响应式降级。
- `h5/index.html`：**独立 H5 形态**。底部 5 个 Tab + 任务详情；连接本地服务时读取真实索引，未连接时使用演示数据并标注。

| 原型页面 | hash | 对应需求 |
|---|---|---|
| 仪表盘 | `#dash` | FR-UI-01 / 03 |
| 任务列表 | `#tasks` | FR-UI-03 |
| 任务详情 | `#task/t1` | FR-UI-02 |
| 待办事项 | `#todos` | FR-NM-06 |
| 文件与空间 | `#files` | FR-NM-04 / FR-UI-06 |
| Agent 管理 | `#agents` | FR-SC-02 / 03 / 04 |
| 扫描调度 | `#sched` | FR-SCH-01 ~ 05 |
| Agent 接入 | `#conn` | FR-MCP-01 / 02 |
| 系统架构 | `#arch` | §3 技术架构 |
| 设置 | `#set` | FR-CFG-01 ~ 04 |

H5 路由（`h5/index.html`）：`#/home` 概览、`#/tasks` 任务、`#/todos` 待办、`#/space` 空间、`#/me` 我的、`#/task/<id>` 详情；二级页 `#/config` 配置中心、`#/sched` 扫描调度、`#/conn` Agent 接入、`#/arch` 系统架构、`#/report` 日报设置。二级页承载 FR-CFG-01/02/03（监控对象启停、路径覆盖、自定义适配器）、FR-SCH-01（调度规则与扫描历史）、FR-MCP-01/02（工具清单与客户端接入）的移动端视图；概览的时间范围切换与日报导出对应 FR-UI-02 / FR-RPT-01。H5 与主视图功能对等，差异仅在信息密度。

### 5.1 Dashboard 主视图

自上而下六个区块：

1. **顶栏**：产品名 + 时间范围选择（今日/本周/本月/自定义）+ Agent 筛选 + 状态筛选 + 「立即扫描」按钮 + 上次扫描时间 + 守护进程状态。
2. **KPI 卡片行（6 张）**：会话总数 / 任务总数 / 活跃时长总计 / 占用空间总计 / 待办数量 / 中断数量。
3. **图表区（左：Agent 维度耗时与任务数分布；右：近 14 天活跃趋势）**。
4. **任务明细表**：Agent | 任务标题 | 项目 | 起止时间 | 耗时（活跃/墙钟）| 状态 | 空间 | 产物数 —— **点击任意行进入详情页**。
5. **待办与中断双栏**：左侧跨 Agent 汇总待办（可勾销），右侧中断任务列表（含中断原因与「最后一条消息」摘要）。
6. **中间文件与空间**：各 Agent 占用排行 + 可回收中间文件清单（只提示，不自动删）。

### 5.2 任务详情页

- 顶部：返回、Agent 徽标、标题、状态徽章、项目路径、起止时间、耗时、占用空间。
- 区块 A：**概览**——一句话结论（做了什么）、关键统计。
- 区块 B：**时间线**——用户消息 / 助手消息 / 工具调用按时序排列，工具调用折叠显示参数摘要。
- 区块 C：**产出文件**——交付物与中间文件分列，中间文件标注「可回收」。
- 区块 D：**待办**——抽取出的勾选项。
- 区块 E：**原始记录**——源文件路径、指纹、所属会话 ID，支持在文件管理器中打开。

### 5.3 设置页

- Agent 列表：名称、启用开关、默认路径、自定义路径、安装检测状态、会话数、占用空间、解析器版本。
- 新增自定义 Agent 表单：名称 / 图标 / 路径 / 通配符 / 解析方式（JSONL / SQLite / 目录树）/ 字段映射。
- 扫描策略：间隔扫描、每日定点、每周、扫描窗口、是否生成日报、日报模板编辑。
- 数据与隐私：索引位置、备份/恢复、隐私说明。

### 5.4 主视图与 H5 的差异

同一套数据，两种信息密度。**不做两套视觉，只做两套排布**——组件样式与状态语义完全一致。

| 项 | 主视图（Obsidian 主区域） | H5（独立版） |
|---|---|---|
| 导航 | 左侧竖排，9 个页面 | 底部 Tab 5 项，设置下沉到「我的」 |
| 任务呈现 | 8 列表格 | 卡片（标题 2 行 + 状态徽标 + 3 项页脚） |
| 筛选 | 下拉 + 分段控件 | 横向 chips + 搜索框 |
| 待办勾销 | 即时重渲染 | 勾选 + `localStorage` 持久化 + Toast |
| 刷新 | 「立即扫描」按钮 | 按钮 + 下拉刷新手势 |
| 写能力 | 全部（含路径配置、调度、备份恢复） | **无**：只读查看 + 待办勾销 |
| 主题 | 跟随 Obsidian CSS 变量 | 跟随 `prefers-color-scheme` |

响应式断点（主区域可被拖拽分屏，宽度连续变化，必须降级）：

| 宽度 | 导航 | KPI | 任务呈现 | 图表 |
|---|---|---|---|---|
| ≥1100px | 左侧竖排 | 6 列 | 8 列表格 | 左右两栏 |
| 900–1100px | 左侧竖排 | 3 列 | 8 列表格，列宽压缩 | 上下堆叠 |
| 620–900px | 顶部横条 | 2 列 | 卡片化 | 上下堆叠 |
| <620px | 顶部横条 | 2 列 | 卡片化，隐藏「项目 / 起止」 | 仅 Agent 分布 |

写能力只在主视图与 CLI 暴露，是刻意设计：H5 可能被手机或副屏打开，破坏性操作必须有完整的确认链路。

## 6. 接入方式

### 6.1 Obsidian 插件（主视图形态）

- Ribbon 图标 → 打开或聚焦**主区域标签页**（`workspace.getLeaf('tab')`），已存在则不重复创建。
- **不注册右侧栏 Leaf**；若后续需要「边写边看」，用 H5 + iframe 内嵌替代，不维护第二套 UI。
- 命令面板命令：
  - `AgentCenter: 打开任务中心`
  - `AgentCenter: 立即扫描`（不打开视图，后台执行后 Toast 摘要）
  - `AgentCenter: 生成今日日报`
  - `AgentCenter: 打开设置`
- 视图路由：`#dash` / `#tasks` / `#task/<id>` / `#todos` / `#files` / `#agents` / `#sched` / `#conn` / `#set`。
- 渲染方式：原生 DOM + Obsidian API，无前端框架依赖，兼容 Obsidian 1.4+。
- 视图生命周期与扫描调度解耦：关闭标签页不停止后台扫描。

### 6.2 MCP Server（供各 Agent 工具接入）

| 工具 | 参数 | 返回 |
|---|---|---|
| `agentcenter_summary` | `start`, `end`, `groupBy` | 周期汇总：任务数、耗时、空间、按 Agent 分布 |
| `agentcenter_list_sessions` | `agent?`, `status?`, `since?`, `limit?` | 任务清单 |
| `agentcenter_get_session` | `taskId` 或 `sessionId` | 单任务详情（含时间线、文件、待办） |
| `agentcenter_list_todos` | `status?`, `agent?` | 待办清单 |
| `agentcenter_storage_report` | `agent?`, `includeIntermediate` | 空间占用与中间文件报告 |
| `agentcenter_trigger_scan` | `agents?` | 触发一次扫描，返回摘要 |

各 Agent 接入方式：
- **WorkBuddy / CodeBuddy**：写入 `~/.workbuddy/mcp.json`，重启后信任。
- **Claude Code**：`claude mcp add` 或 `~/.claude.json`。
- **Qoder / DeepSeek / Trae / 其他**：按各自 MCP 配置文件格式添加 stdio 服务。

### 6.3 CLI

```bash
agentcenter scan [--agents a,b] [--full]      # 执行扫描
agentcenter summary --start 2026-10-29 --end 2026-10-29 [--json]
agentcenter todos [--status pending] [--json]
agentcenter storage [--agent workbuddy] [--json]
agentcenter report --date 2026-10-29 --out <path>
agentcenter mcp                                  # 启动 MCP stdio 服务
```

### 6.4 H5 独立版与本地服务

H5 不依赖 Obsidian，但需要本机常驻服务提供数据与静态资源（否则浏览器无法读取本地索引）。

```bat
h5\start-h5.cmd                :: 启动服务（默认 127.0.0.1:7788）并打开 430x900 App 窗口
h5\start-h5.cmd 8899           :: 指定端口
h5\stop-h5.cmd                 :: 按端口结束进程
powershell -ExecutionPolicy Bypass -File h5\autostart-install.ps1            :: 写入开机自启（启动文件夹）
powershell -ExecutionPolicy Bypass -File h5\autostart-install.ps1 -Task      :: 改用计划任务
powershell -ExecutionPolicy Bypass -File h5\autostart-install.ps1 -Uninstall :: 取消自启
```

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/health` | GET | 运行状态、版本、上次扫描时间、数据文件位置 |
| `/api/summary?range=today` | GET | 真实索引；文件缺失时返回 503，前端回退演示数据 |
| `/api/scan` | POST | 预留，当前返回 501（写能力不通过 HTTP 暴露） |

约束：仅绑定 `127.0.0.1`，不监听局域网；服务与浏览器解耦，关闭窗口不中断扫描；日志位于 `%LOCALAPPDATA%\AgentCenter\h5.log`。完整规格见 `展示形态与H5方案.md`。

## 7. Agent 适配器规格

每个适配器实现统一接口：

```ts
interface AgentAdapter {
  id: string;
  displayName: string;
  defaultPaths: { win: string[]; mac: string[]; linux: string[] };
  detect(): Promise<{ installed: boolean; version?: string; sessionCount: number }>;
  listSessions(): Promise<RawSession[]>;
  parseSession(raw: RawSession): Promise<TaskRecord[]>;
  listArtifacts(session: RawSession): Promise<ArtifactRef[]>;
}
```

内置适配器默认路径表与实测状态见 `docs/Agent适配器规格.md`（含每种格式的字段映射与解析示例）。

**扩展机制**：自定义 Agent 走「通用 JSONL 适配器」，用户只需指定路径 + 通配符 + 关键字段映射（时间字段、角色字段、内容字段、工具字段），即可完成采集。

## 8. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 插件 | TypeScript + Obsidian API | 官方标准，无构建负担 |
| 内核 | Node.js，尽量零运行时依赖 | 便于 CLI/MCP/守护进程三种形态复用 |
| 存储 | JSON 文件（分月分片） | 可读、可 diff、可备份，避免 SQLite 原生依赖 |
| 图表 | 原生 SVG / 轻量 Chart.js | Obsidian 环境内避免重型依赖 |
| 调度 | 插件内 `setInterval` + 外部守护进程（可选 npm 包/系统计划任务） | 覆盖 Obsidian 开/关两种场景 |
| 外部调度注册 | Windows 任务计划 / macOS launchd / systemd timer / cron | 跨平台，用户零学习成本 |

**关键取舍**：Obsidian 插件内调度仅在 Obsidian 运行期间生效。要做到「关闭 Obsidian 也能每天 17:00 出日报」，必须依赖外部守护进程或系统计划任务——这是 v1 的必要设计，而非可选项。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Agent 升级导致会话格式变化 | 解析失效 | 适配器版本化 + 解析失败降级为「原始片段展示」+ 指纹回归测试 |
| 误报/漏报任务状态 | 结论不可信 | 状态判定必须携带 `statusReason`，可追溯；提供「手动修正」入口 |
| 扫描性能（Agent 累积数年数据） | 首次扫描慢 | 增量扫描 + 首扫限流 + 后台分片 + 进度条 |
| 用户担心隐私 | 拒绝使用 | 全本地只读；隐私说明页；提供「仅扫描指定目录」开关 |
| 磁盘占用增长 | 用户困扰 | 中间文件视图只提示不自动删；提供回收建议与手动确认流程 |
| Obsidian 未运行时无定时产出 | 定时任务失效 | 外部守护进程/系统计划任务兜底 |

## 11. 验收标准（v1.0）

1. 在一台同时安装 ≥4 个 Agent 工具的机器上，一次扫描能正确列出全部工具的近 30 天会话，任务标题与时间准确率 ≥ 95%。
2. Dashboard 各区块数据与底层索引一致；点击任务行 1 步内进入详情页。
3. `agentcenter summary --start <今天> --end <今天>` 输出的任务数、耗时、空间与 Dashboard 当日视图完全一致。
4. 关闭 Obsidian 后，系统计划任务仍能生成当日日报 Markdown。
5. 在 WorkBuddy/Claude Code 中调用 `agentcenter_summary` 能得到结构化答复，数据与 Dashboard 一致。
6. 扫描前后，11 个 Agent 的源数据目录文件数与 `mtime` 全部不变（只读验证通过）。
7. 用户可在设置页新增一个自定义 Agent（指向任一 JSONL 会话目录）并成功采集出任务。
8. 点击 Ribbon 后主区域出现「任务中心」标签页，右侧栏无新增面板；分屏至 480px 宽时无横向滚动条。
9. H5 在 390px 与 820px 视口下无横向溢出，5 个 Tab 与任务详情均可达；服务未启动时标注「演示数据」且功能不阻塞。
10. 注册开机自启后重新登录，5 秒内 `/api/health` 返回 200；关闭浏览器进程后服务仍在运行。
