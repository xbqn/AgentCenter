# AgentCenter 展示形态调整与 H5 独立版方案

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.2（评审稿） |
| 日期 | 2026-10-29 |
| 变更来源 | 评审意见：不使用侧边栏形态，改为主区域展示；新增可在 Obsidian 之外独立运行的 H5 |
| 关联文档 | `需求规格方案.md`、`Agent适配器规格.md` |

---

## 1. 本次变更

| 项 | v0.1 | v0.2 |
|---|---|---|
| Obsidian 形态 | 右侧边栏面板（Sidebar Leaf） | **主区域标签页（Main Area Tab）**，可与笔记分屏 |
| 侧边栏 | 核心视图之一 | **取消**，仅在 Ribbon 保留入口图标 |
| 外部形态 | 无 UI，仅 CLI / MCP | 新增 **H5 独立版（PWA）**，浏览器直接可用 |
| 常驻方式 | 外部守护进程仅用于定时扫描 | 守护进程同时充当 **H5 本地服务**，支持开机自启 |
| 数据契约 | 插件内部 `index.json` | 抽出 **HTTP `/api/summary`**，三端共用同一索引 |

变更的动机不是「多做一个界面」，而是评审指出的一个实际问题：**侧边栏宽度不足**。任务列表需要 Agent、标题、耗时、状态、空间五列信息，可用宽度低于 700px 时只能压缩成三行卡片，信息密度和主视图差距过大，等于维护两套渲染逻辑。改为主区域后，只需一套渲染 + 一组响应式断点。

---

## 2. 三种展示形态

| 形态 | 宿主 | 入口 | 能力 | 典型场景 |
|---|---|---|---|---|
| **主视图** | Obsidian 主进程 | Ribbon 图标 / 命令面板 / URI | 全功能：看板、详情、设置、生成日报 | 日常回看，与笔记分屏对照 |
| **H5 独立版** | 浏览器 / PWA | `http://127.0.0.1:7788/` | 查看与勾销待办，只读；不含设置写操作 | 不开 Obsidian、手机同网段（默认关闭）、双屏副屏 |
| **CLI / MCP** | 终端 / 任意 Agent | `agentcenter ...` / MCP 工具 | 查询、触发扫描、取日报 | 被 WorkBuddy、Claude Code 等反查 |

三者**共用同一扫描内核与同一份索引**，不允许各自维护数据副本。验收条款 3 与 7 就是卡这一点。

## 3. Obsidian 主视图规格

### 3.1 打开方式

```ts
const VIEW_TYPE = 'agentcenter-main';

// 主区域标签页，而非 getRightLeaf
async function activateView(plugin: Plugin) {
  const { workspace } = plugin.app;
  let leaf: WorkspaceLeaf | null = null;
  workspace.getLeavesOfType(VIEW_TYPE).forEach((l) => { if (!leaf) leaf = l; });
  if (!leaf) {
    leaf = workspace.getLeaf('tab');          // 关键：主区域
    await leaf.setViewState({ type: VIEW_TYPE, active: true });
  }
  workspace.revealLeaf(leaf);
  return leaf;
}
```

| 入口 | 行为 |
|---|---|
| Ribbon 图标 | 打开或聚焦主视图标签页（已存在不重复创建） |
| 命令 `AgentCenter: 打开任务中心` | 同上 |
| 命令 `AgentCenter: 立即扫描` | 不打开视图，后台扫描后 Toast 摘要 |
| 命令 `AgentCenter: 生成今日日报` | 写入 Vault 并弹出打开链接 |
| URI `obsidian://agentcenter?route=tasks` | 供 H5「在 Obsidian 中打开」跳转 |
| 任务行 | 视图内二级页面（`#task/<id>`），不新开标签，避免标签爆炸 |

### 3.2 视图生命周期

- `ItemView.getViewType()` 返回 `agentcenter-main`，`getDisplayText()` 返回「任务中心」。
- `onOpen()` 注册渲染与 `index.json` 变更订阅；`onClose()` 解除订阅，停止 UI 层定时器。
- 扫描由**独立调度器**驱动，不绑定视图生命周期——关闭标签页不应停止后台扫描。
- 视图重建时从索引读取，不做全量重扫；仅在索引版本落后时触发增量扫描。

### 3.3 响应式断点

主区域可被拖拽分屏，宽度是连续变量，必须按断点降级：

| 宽度 | 导航 | KPI | 表格 | 图表 |
|---|---|---|---|---|
| ≥1100px | 左侧竖排导航（212px） | 6 列 | 8 列表格 | 左右两栏 |
| 900–1100px | 左侧竖排导航 | 3 列 | 8 列表格，列宽压缩 | 上下堆叠 |
| 620–900px | 顶部横条导航 | 2 列 | 卡片化列表 | 上下堆叠 |
| <620px | 顶部横条导航 | 2 列 | 卡片化，隐藏「项目」「起止」 | 仅保留 Agent 分布 |

原型已内置「主视图 / 分屏 480」切换，用于直接检查降级效果——**不横向溢出**是硬要求。

### 3.4 与侧边栏方案的取舍

| 维度 | 侧边栏 | 主视图（采纳） |
|---|---|---|
| 信息密度 | 300px 宽，任务表需重排为卡片 | 完整表格，一次看 8 列 |
| 维护成本 | 需两套渲染逻辑 | 一套 + 断点 |
| 与笔记协同 | 常驻右侧，占空间 | 分屏，比例可调 |
| 打开成本 | 一次点击 | 一次点击（标签页记忆） |
| 风险 | 信息被压缩后判读效率下降 | 标签页过多时需清理 |

结论：**放弃侧边栏**。若后续确有「边写边看今日概况」的需求，用 H5 副屏或 Obsidian 内嵌 iframe（`<iframe src="http://127.0.0.1:7788/">`）替代，比维护第二套 UI 更划算。

### 3.5 主题映射

不得硬编码颜色。原型使用 CSS 变量名与 Obsidian 语义变量一一对应：

| 原型变量 | Obsidian 变量 |
|---|---|
| `--bg` | `--background-primary` |
| `--surface` | `--background-primary-alt` |
| `--surface2` | `--background-secondary` |
| `--line` / `--line2` | `--background-modifier-border` / `-hover` |
| `--tx` / `--tx2` / `--tx3` | `--text-normal` / `--text-muted` / `--text-faint` |
| `--blue` | `--interactive-accent` |

品牌色（Agent 徽标、状态色）保留固定色板，确保跨主题语义一致：状态色是信息，不是装饰。

## 4. H5 独立版

### 4.1 定位与边界

**做**：只读查看、待办勾销（本地持久化）、详情下钻、空间排行、PWA 安装、离线外壳。
**不做**：Agent 路径配置、扫描策略修改、文件回收、任何写源目录的操作。这些留在主视图与 CLI。

原因：H5 可能被手机或副屏打开，写操作的确认链路与权限提示难以做到和桌面一致；把破坏性能力收敛到单一入口，是安全边界的一部分。

### 4.2 信息架构

v0.3 起为桌面端布局：左侧竖排导航 + 顶部标题栏 + 宽屏网格/表格。导航分三组：

| 分组 | 路由 | 内容 |
|---|---|---|
| 工作台 · 概览 | `#/home` | 时间范围（今日 / 近 7 天 / 近 14 天）、渐变横幅、4 张 KPI、近 14 天趋势、中断提醒、Agent 分布、日报导出、最近任务表格 |
| 工作台 · 任务 | `#/tasks` | 搜索 + 5 个状态筛选 + Agent 维度筛选 + 表格列表（状态 / 任务与工作目录 / Agent / 活跃 / 空间 / 起止） |
| 工作台 · 待办 | `#/todos` | 4 张 KPI（未完成 / 已完成 / 待确认 / 中断遗留）+ Agent 筛选 + 未完成与已完成分组 + 导出清单 |
| 工作台 · 空间 | `#/space` | 总占用 / 交付物 / 中间文件 / 高优先级 4 张 KPI、中间文件清单与 Agent 根目录占用双栏、导出清单 |
| 监控对象 | `#/config` | 11 个监控对象启停与路径覆盖（双列网格）、自定义 Agent 适配器、调度摘要、恢复默认路径 |
| 扫描调度 | `#/sched` | 4 条调度规则（轮询 / 日报 / 周度盘点 / 全量重建）+ 最近 6 轮扫描历史 |
| Agent 接入 | `#/conn` | MCP 6 个工具清单、4 个客户端接入配置、CLI 命令示例 |
| 系统架构 | `#/arch` | 采集 / 解析 / 索引 / 呈现四层数据流、三种形态、4 条关键边界 |
| 日报设置 | `#/report` | 日报目录与模板、自动生成开关、索引位置与备份、增量扫描与扫描窗口、隐私说明 |
| 设置与关于 | `#/me` | 服务状态、上次扫描与立即扫描、自启开关、PWA 安装、隐私说明 |
| 任务详情 | `#/task/<id>` | 元信息、状态依据、时间线、产出文件、待办、原始路径 |

全部 11 个页面一级直达，不再有底部 Tab 与二级折叠。窄于约 900px 时左侧导航收起为顶部横向条，KPI 降为两列，布局不破。

### 4.3 桌面与移动的差异

| 项 | 主视图 | H5 |
|---|---|---|
| 任务呈现 | 8 列表格 | 卡片（标题 2 行截断 + 状态徽标 + 工作目录路径行 + 3 项页脚） |
| 物理路径 | 表格标题列下附工作目录；详情页列工作目录与会话源文件 | 同左，卡片内路径中间省略、`title` 悬停看全量；详情页按 `\` 分隔符换行 |
| 筛选 | 顶部下拉 + 分段控件 | 横向 chips + 搜索框 |
| 待办勾销 | 即时重渲染 | 勾选 + `localStorage` 持久化 + Toast |
| 刷新 | 「立即扫描」按钮 | 按钮 + 下拉刷新手势 |
| 导航 | 左侧竖排 | 底部 Tab + 安全区适配 |

### 4.4 数据来源与降级

```
H5 (index.html)
  ├─ GET /api/health   → 顶栏连接状态、上次扫描时间
  └─ GET /api/summary  → 真实索引；失败则使用内置演示数据
```

- 服务可达：顶栏显示「本地服务已连接」，绿点常亮。
- 服务不可达（`file://` 直接打开、服务未启动）：显示「演示数据」，**不阻塞评审**，也不弹错误框。
- 该降级路径是刻意保留的：直接用浏览器打开 `h5/index.html` 就能评审，无需先装 Node 环境。

### 4.5 离线与缓存

- `sw.js` 只缓存应用外壳（HTML / manifest / icon），**不缓存 `/api/*`**，避免看到过期任务数据。
- 导航请求网络优先、失败回退缓存；静态资源缓存优先 + 后台更新。
- `file://` 协议下不注册 Service Worker（浏览器限制），PWA 安装仅在 `http://127.0.0.1` 下可用。

## 5. 本地服务与自启动

### 5.1 进程模型

```
开机 / 手动启动
  └─ start-h5.cmd
       └─ node serve.mjs  (127.0.0.1:7788, 零依赖)
            ├─ 静态托管 h5/
            ├─ /api/health  运行状态
            └─ /api/summary 读取 data/summary.json（由扫描内核写入）
浏览器 --app=http://127.0.0.1:7788 --window-size=430,900
```

关键设计：**服务与浏览器解耦**。关闭浏览器窗口不停止服务，扫描与日报继续；服务退出也不影响已生成的索引文件。

### 5.2 脚本清单

| 文件 | 作用 |
|---|---|
| `h5/serve.mjs` | 零依赖 Node 服务，默认 7788，仅绑定 `127.0.0.1` |
| `h5/start-h5.cmd` | 幂等启动（已运行则复用）+ 以浏览器 App 模式打开 430×900 窗口 |
| `h5/stop-h5.cmd` | 按端口查 PID 并结束进程 |
| `h5/autostart-install.ps1` | 写「启动」文件夹快捷方式；`-Task` 改用计划任务（登录后延迟 30s）；`-Uninstall` 卸载 |

启动脚本对浏览器做顺序探测：`%LOCALAPPDATA%` → `D:\Users\<用户>\AppData\Local` → `Program Files` → `Program Files (x86)`（Chrome 优先，其次 Edge），全部未命中则退回默认浏览器开普通标签。

### 5.3 自启动三方案

| 方案 | 生效时机 | 权限 | 资源占用 | 适用 |
|---|---|---|---|---|
| 启动文件夹快捷方式（默认） | 用户登录 | 无需管理员 | 常驻约 30–50 MB | 个人机，推荐 |
| 计划任务 `-Task` | 登录后 30s | 通常无需提权 | 同上，可控延迟 | 希望错峰启动 |
| Obsidian 插件内启动 | 打开 Obsidian | 无需 | 依附 Obsidian | 不想常驻后台，但牺牲「Obsidian 未开也能用」 |

隐私取舍：本地服务常驻意味着「随时可查」，也意味着端口长期占用。默认仅 `127.0.0.1`，不对局域网开放；如后续需要手机访问，必须显式开启并配访问令牌（见 §8）。

### 5.4 端口与安全

- 默认 `7788`，可通过 `start-h5.cmd 8899` 或 `AC_PORT` 覆盖。
- 绑定地址硬编码 `127.0.0.1`，不做配置项，从设计上排除局域网暴露。
- 当前 API 只读；`/api/scan` 返回 501，写能力不通过 HTTP 暴露。
- 服务以最小化控制台窗口运行（标题 `AgentCenterH5`），便于现场查看输出与 `Ctrl+C` 退出；同时日志落盘至 `%LOCALAPPDATA%\AgentCenter\h5.log`，窗口被关闭后仍可回溯启动失败原因。

## 7. 验收标准（本次新增）

1. Obsidian 中点击 Ribbon 后，**主区域**出现「任务中心」标签页，右侧栏无新增面板。
2. 主视图分屏至 480px 宽时，页面**不出现横向滚动条**，KPI 为 2 列，任务表转为卡片。
3. H5 在 390px 与 820px 视口下均无横向溢出，5 个 Tab 与任务详情可达。
4. 服务未启动时直接打开 `h5/index.html`，页面正常渲染并明确标注「演示数据」。
5. 开机自启后 5 秒内 `/api/health` 返回 200；关闭浏览器进程后再次访问仍可用。
6. 扫描前后，11 个 Agent 源目录的文件数与 `mtime` 不变（沿用 v0.1 第 6 条）。

## 8. 待评审确认

1. **是否默认开机自启**：常驻更省事，但会长期占用端口与约 40 MB 内存。当前脚本需手动执行一次安装。
2. **端口策略**：固定 7788 便于收藏与 iframe 内嵌，但冲突时需人工换端口；是否改为冲突自动递增？
3. **是否引入访问令牌**：一旦开放局域网访问（手机查看），必须加 token；若明确只用回环地址，可省。
4. **是否保留侧边栏精简视图**：本方案已取消；若你仍希望「边写笔记边看今日三行摘要」，建议用 iframe 嵌入而非重写 UI，需确认是否纳入 v1。
5. **移动端远程访问**：当前明确不做。若要做，需要反向代理 + 鉴权 + HTTPS，工作量约 2–3 天，且扩大攻击面。
